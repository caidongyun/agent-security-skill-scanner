## 🎯 根本原因

### 问题 1: 检测规则过于敏感

**当前规则**:
- `curl|bash` → 直接判定恶意
- `subprocess` → 判定恶意
- `eval/exec` → 判定恶意

**问题**: 这些模式在**良性安装脚本**中也很常见

---

### 问题 2: 缺少上下文判定

**当前逻辑**:
```python
if 'curl|bash' in content:
    verdict = 'MALICIOUS'  # 直接判定
```

**应该**:
```python
if 'curl|bash' in content:
    # 检查是否是安装脚本
    if is_install_script and has_documentation:
        verdict = 'SUSPICIOUS'  # 可疑，非恶意
    else:
        verdict = 'MALICIOUS'
```

---

### 问题 3: 缺少领域判定

**问题**: 安全审计类 Skills 本身就包含检测代码  
**表现**: `auditclaw-*` 系列被判定为恶意

---

## ✅ 正确优化方向

### 方案 1: 调整检测阈值

**当前**: 检测到 `curl|bash` 就判定恶意  
**优化**: 结合文件类型、路径、文档综合判定

```python
# 安装脚本中的 curl|bash 降低风险
if is_install_script():
    risk_score *= 0.5
```

---

### 方案 2: 领域感知辅助

**使用领域分类**:
```python
domain = classify_domain(skill_content)

if domain == 'security_audit':
    # 安全审计类 Skills 包含检测代码是正常的
    risk_score *= 0.7
```

---

### 方案 3: 白名单机制

**官方 Skills 白名单**:
```python
OFFICIAL_SKILLS = [
    'auditclaw-*',
    'agent-*',
    'skills-*',
]

if skill_name in OFFICIAL_SKILLS:
    risk_score *= 0.8
```
